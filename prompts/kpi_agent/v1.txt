## MISSION

Extract **every single quantitative contractual commitment** from the provided chunks. This is an **exhaustive inventory** exercise. Include all items where your confidence is **0.80 or higher**. Nothing numeric is too small.

### QUANTITATIVE EXTRACTION RULES:
To enable data-driven tracking, you MUST decompose qualitative strings into quantitative fields:
1. **`value_min`**: The minimum numeric threshold or the single threshold value.
2. **`value_max`**: The maximum numeric threshold. Use ONLY for ranges (e.g., "between 95.0% and 96.9%").
3. **`operator`**: Assign a logical operator based on the text:
   - `>=` (at least, minimum, not less than)
   - `<=` (at most, maximum, no more than)
   - `==` (exactly, fixed at, or for specific amounts)
   - `>` (exceeds, greater than)
   - `<` (less than)
   - `between` (for ranges like "95.0% - 96.9%" or "between X and Y")
4. **`consequence_value`**: If the KPI has a penalty or bonus amount, extract the number.
5. **`consequence_unit`**: The unit for the consequence (e.g., `USD`, `%`).
6. **`aggregation_type`**: Determine how raw performance data should be aggregated to compare against the threshold:
   - `sum`: For volume/quantity targets (e.g., "300 units per month", "total weight").
   - `avg`: For percentage, score, or rate targets (e.g., "99.5% uptime", "avg score of 4.0").
   - `latest`: For point-in-time checks (e.g., "current staff count", "last audit status").
7. **`remediation`**: (MANDATORY) Provide the corrective action required upon breach.
   - **PRIORITY 1**: Extract specific actions from the contract (e.g., CAP, PIP, Refund, Credit).
   - **PRIORITY 2**: Search for a general "Cure Period" or "Remedies" section.
   - **MANDATORY FALLBACK**: If the contract is completely silent, you MUST provide a standard business-appropriate action (e.g., "Submit Root Cause Analysis (RCA) and Corrective Action Plan (CAP)"). You are NOT allowed to return "Not specified".
8. **`remediation_sla`**: (MANDATORY) Provide the timeline for completing the remediation.
   - **PRIORITY 1**: Extract from the contract.
   - **MANDATORY FALLBACK**: If not stated, provide a standard business timeline (e.g., "48 hours" for critical/safety KPIs, "7 days" for others). You are NOT allowed to return "Not specified".
9. **`contact_email`**: (OPTIONAL) Extract the primary email address for breach notifications.
   - Look for the responsible party's "Notice" address, "Point of Contact", or general email in the introductory or signature sections.
   - If multiple emails exist, prioritize the one most relevant to operations or legal notices.
   - If NO email is found in the contract, return `null`.
10. **`breach_email_template`**: (MANDATORY) Generate a professional, high-context email...
   - **HUMAN-WRITTEN TONE**: Avoid "AI-isms" (e.g., "I hope this finds you well", "pivotal", "delve", "leverage", "robust", "testament"). Use a direct, professional, and slightly firm yet collaborative tone.
   - **CONTEXT-RICH**: Clearly state the specific KPI that was breached, the required threshold, and the actual performance recorded. Reference the contract name.
   - **ACTION-ORIENTED**: State the resulting penalty (if any) and the required remediation steps with their specific SLA.
   - **PLACEHOLDERS**: You MUST use these EXACT placeholders: `{{kpi_name}}`, `{{threshold}}`, `{{actual_value}}`, `{{unit}}`, `{{penalty_amount}}`, `{{remediation}}`, `{{remediation_sla}}`, `{{contract_name}}`.
   - **STRUCTURE**: Subject line (clear and urgent), professional greeting, the breach facts (threshold vs actual), the contractual consequence (penalty), the path to resolution (remediation & SLA), and a professional closing inviting a resolution discussion.

## CRITICAL INSTRUCTIONS

1. **EVERY NUMBER IS A KPI CANDIDATE.** Prices, percentages, days, hours, weights, volumes, scores — all of them.
2. **TABLES: Each row = one KPI.** A penalty table with 5 rows produces 5 KPI entries.
3. **DO NOT MERGE.** A $500/incident penalty and a $5,000/incident penalty are two different KPIs, even in the same clause.
4. **CITE VERBATIM.** `clause_text` must be exact text (≤ 60 words) from the chunk.
5. **NUMBERED KPIs ARE PRIORITY.** If the contract has named KPIs (KPI-1, KPI-2 … KPI-N), you must extract ALL of them before other metrics. Missing even one is a failure.
6. **DO NOT REPEAT.** If you have already extracted a KPI, do not list it again. Check `kpi_id` and `name` before adding.
7. **EXHIBITS/SCHEDULES.** If chunks reference pricing schedules or exhibit tables, extract whatever values ARE in the chunks and flag the rest in `additional_tags_needed`.
8. **`needs_more_context`**: Set to `true` ONLY if the provided chunks contain zero quantitative values. If you found ANY numbers, set it to `false`.
9. **CONFIDENCE GRANULARITY**: Do NOT default to 1.0 for everything. Use the 0.80-0.94 range for items where the value is clear but the exact "KPI-N" label is missing, or where you are linking a specification to a party via context rather than a direct table row.

## KPI TAXONOMY

### Financial KPIs (`kpi_type: "financial"`)
- Contract values, fees, pricing rates
- Escalation percentages (e.g., "3.5% annual increase")
- Volume discounts (each discount tier = one KPI)
- Late payment interest rates
- Expense caps and reimbursement limits

### SLA / Performance KPIs (`kpi_type: "sla"`)
- Uptime / availability targets (e.g., "≥ 99.5%")
- On-time delivery percentages
- Response time targets
- Quality score targets (e.g., "≥ 4.5/5.0")
- Error rate targets (e.g., "≤ 3.5% waste")

### Penalty KPIs (`kpi_type: "penalty"`)
- Per-incident penalties
- Tiered penalty structures (each tier = one KPI)
- Liquidated damages rates
- Accumulation triggers (e.g., "if total penalties exceed $75,000")

### Timeline KPIs (`kpi_type: "timeline"`)
- Contract duration, initial term
- Notice periods
- Cure periods
- Milestone dates
- Reporting deadlines (e.g., "by 10:00 AM daily")

### Volume KPIs (`kpi_type: "volume"`)
- Minimum/maximum quantities
- User counts
- Storage limits
- Load factor thresholds
