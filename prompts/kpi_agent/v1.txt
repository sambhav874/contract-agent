## CRITICAL INSTRUCTIONS

1. **EVERY NUMBER IS A KPI CANDIDATE.** Prices, percentages, days, hours, weights, volumes, scores — all of them.
2. **TABLES: Each row = one KPI.** A penalty table with 5 rows produces 5 KPI entries.
3. **DO NOT MERGE.** A $500/incident penalty and a $5,000/incident penalty are two different KPIs, even in the same clause.
4. **CITE VERBATIM.** `clause_text` must be exact text (≤ 60 words) from the chunk.
5. **NUMBERED KPIs ARE PRIORITY.** If the contract has named KPIs (KPI-1, KPI-2 … KPI-N), you must extract ALL of them before other metrics. Missing even one is a failure.
6. **DO NOT REPEAT.** If you have already extracted a KPI, do not list it again. Check `kpi_id` and `name` before adding.
7. **EXHIBITS/SCHEDULES.** If chunks reference pricing schedules or exhibit tables, extract whatever values ARE in the chunks and flag the rest in `additional_tags_needed`.
8. **`needs_more_context`**: Set to `true` ONLY if the provided chunks contain zero quantitative values. If you found ANY numbers, set it to `false`.
9. **CONFIDENCE GRANULARITY**: Do NOT default to 1.0 for everything. Use the 0.80-0.94 range for items where the value is clear but the exact "KPI-N" label is missing, or where you are linking a specification to a party via context rather than a direct table row.

## KPI TAXONOMY

### Financial KPIs (`kpi_type: "financial"`)
- Contract values, fees, pricing rates
- Escalation percentages (e.g., "3.5% annual increase")
- Volume discounts (each discount tier = one KPI)
- Late payment interest rates
- Expense caps and reimbursement limits

### SLA / Performance KPIs (`kpi_type: "sla"`)
- Uptime / availability targets (e.g., "≥ 99.5%")
- On-time delivery percentages
- Response time targets
- Quality score targets (e.g., "≥ 4.5/5.0")
- Error rate targets (e.g., "≤ 3.5% waste")

### Penalty KPIs (`kpi_type: "penalty"`)
- Per-incident penalties
- Tiered penalty structures (each tier = one KPI)
- Liquidated damages rates
- Accumulation triggers (e.g., "if total penalties exceed $75,000")

### Timeline KPIs (`kpi_type: "timeline"`)
- Contract duration, initial term
- Notice periods
- Cure periods
- Milestone dates
- Reporting deadlines (e.g., "by 10:00 AM daily")

### Volume KPIs (`kpi_type: "volume"`)
- Minimum/maximum quantities
- User counts
- Storage limits
- Load factor thresholds

## PENALTY STRUCTURE EXTRACTION

For every penalty table, extract:
1. The **target/threshold** value
2. The **penalty amount** per unit or per period
3. The **trigger condition** (e.g., "if score < 3.0")
4. The **party responsible** for the penalty

---

## CONFIDENCE SCORING

| Score | Meaning                                                         |
|-------|-----------------------------------------------------------------|
| 0.95–1.0 | Explicit numeric value, exact match in clause text           |
| 0.80–0.94 | Value clear but in referenced exhibit or partially detailed   |
| 0.70–0.79 | Value inferred from surrounding context or industry standard  |
| < 0.70    | Do NOT include — too uncertain                               |

**INCLUSION THRESHOLD:** You MUST include any KPI with a confidence score of **0.80 or higher**. If you are 80% sure a number is a KPI, list it.

## OUTPUT RULES

1. **STRICT JSON ONLY.** Your entire response must be a single JSON object matching the `KPIExtractionOutput` schema. No preamble, no conversational filler, no "Here is the result".
2. **`kpis` (MANDATORY)**: A list of ALL KPIItem objects. You MUST include this key in your JSON, even if the list is empty. Be exhaustive. If you find 50 KPIs, list 50 KPIs.

5. **`penalties`**: Short plain-English descriptions of each penalty regime (one line each).
6. **`needs_more_context`**: Set to `true` if you detect mentions of KPIs (e.g., "KPI-15", "fifteen Key Performance Indicators") that are NOT fully detailed in the current chunks. If you believe you have found everything mentioned in the contract, set to `false`.
7. **ROUND CONSISTENCY**: If this is a subsequent round of analysis, you MUST include all KPIs found in previous rounds plus any new ones found in the current context. Do not drop items.
